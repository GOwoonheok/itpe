# exec-plan: 면접 문항 300 재구성 + 회독 최적화 UI (소개하기·선택토픽)

- 날짜: 2026-07-26
- 유형: 콘텐츠 전면 재생성(면접 문항 ~300) + 앱 기능 추가(소개하기·선택토픽·회독 UI)
- 트리거: 139회 실기(면접) 임박. 남은 ~1주일 **반복 회독**용 도구로 고도화.
- 선행: `2026-07-23-139회-면접문항집-생성.md`(108문항 v1). 본 계획은 그 v1을 **대체**한다.

## 배경 / 목표

v1(108문항)은 답변이 길어 회독 속도가 느리고, 기존 108개에 국한됐다. 이번 개편은:

1. **문항 전면 재구성** — 108 국한 없이 새로 설계. **이력연계 ~100 + 예상토픽 ~200(MECE) = 약 300문항**.
2. **답변 회독 최적화** — 개념은 **두괄식·1분 내외**, 실사례는 **키워드 중심·30초**. 전체 답변 ≈ **1분 30초**.
3. **소개하기 메뉴(신규)** — 자기소개·포부·기술사 윤리강령을 **입력·저장·열람**(localStorage).
4. **선택토픽 관리(신규)** — 카드 ★ 북마크 → 선택 문항만 반복 학습(localStorage).

## 절대규칙 준수

- **동작 임의 변경 금지(규칙1)**: 소개하기·선택토픽은 **신규 추가** 기능이며, 기존 출제 3모드·4단 답변뷰·딥링크·네비게이션 동작은 **불변**. 4단 답변뷰에 keywords/접이식 섹션을 **덧붙이되** 기존 4단 렌더는 그대로.
- **커밋 전 `npm run check`(규칙2)**, **main 푸시 전 fetch/rebase(규칙4)**, **관련 파일만 커밋(규칙5)**.

## A. 데이터 설계 (~300문항)

카테고리 파일·id는 딥링크 안정성을 위해 유지, 표시명만 조정.

| 파일 | id | 표시명 | 규모 | 출제 |
|---|---|---|---|---|
| `career.json` | `career` | 이력연계 토픽 | ~100 | sequence |
| `expected.json` | `expected` | 예상 토픽 | ~200 | shuffle |

**① 이력연계 ~100** — 이력카드 8블록 균형 배분(블록당 ~12~13):
공공AX(바이브코딩·RAG·vLLM·POC·챗봇·상담콜) / AI발주지원(유사도·RFP·규격검토·AI모델·학습데이터·요구관리) / e-발주평가(ITSM·SLA·DRM·직접구매·과심의·화상평가·335억) / 전자정부지원(BPR·ISP·감리·WBS·예산·조달관리) / 행정정보공동이용(데이터표준·코드매핑·G4C·EAI·MVC·단위테스트) / 차세대나라장터950억(발주PM·사업자이탈·화재DR·PMO·CCB·과업심의·7조원) / 전문관·수상·박사논문·겸임교수 / 자격·동기·포부·윤리강령.

**② 예상토픽 ~200 (MECE 8도메인, 도메인당 ~25):**
SW공학/아키텍처 · DB/데이터 · AI/데이터분석 · 네트워크/클라우드/인프라 · 보안 · OS/컴퓨터구조 · PM/프로젝트관리 · 거버넌스/법제도/신기술·시사. 기출 852 빈출 우선.

### 스키마 (기존과 동일 — check.mjs 통과)

```
id, category, block, kind, prob,
question,
restate,     // 복명복창 1줄 (서두공식 최소화)
structure,   // "N가지입니다. 첫째…" 개수선언 목차
concept,     // ★두괄식: 결론 1문장 → 근거 2~3개. ≈300~360자(≈1분)
case,        // ★키워드 중심 간결. 이력 연계·이미지메이킹. ≈150~220자(≈30초)
keywords,    // 핵심 키워드 배열 (UI 신규 노출)
followupGuard, pitfall,  // 접이식 "면접관 압박 대응"으로 노출
references   // string[] (없으면 [])
```

### 답변 스타일 규칙 (docx 교정 반영)

- **두괄식**: concept 첫 문장이 결론. 이어 근거를 **개수 선언**("두 가지입니다. 첫째…").
- **'제가' 주어**, 기관 언급 최소화. **유보어 금지**("~같습니다"→"~입니다").
- **수치 창작 금지**: 미검증 수치는 산출식·'추정' 라벨. 미완 업무는 진행형("현재 ~까지, 다음은 ~").
- **길이 상한 준수**: concept+case 합쳐 낭독 ~90초. 초과분은 followupGuard로 이관.

## B. UI 설계 (`interview.html` / `interview.js` / `interview.css`)

### B-1. 회독 최적화 답변뷰 (기존 4단 뒤에 덧붙임)
`revealAnswer()`에서 4단(restate/structure/concept/case) 렌더 **후**:
- **keywords 칩 행** 추가(빠른 회독의 핵심 앵커).
- `<details>` **"면접관 압박 대응"**(접힘 기본) 안에 `followupGuard` 목록 + `pitfall`.
- 기존 references 렌더는 유지.

### B-2. 선택토픽(★ 북마크)
- 저장: `localStorage["iv:bookmarks"]` = id 배열. 키는 문항 `id`(career-/expected- 유일).
- 학습화면 카드 헤더에 **★ 토글 버튼** 추가 → currentItem 북마크 on/off.
- 메인화면 합성 카드 **"⭐ 선택토픽"**(count = 북마크 수) → 북마크 문항만 `startStudy`. 0개면 안내.
- 딥링크 `?cat=bookmarks` 지원(기존 딥링크 패턴 확장).

### B-3. 소개하기 (자기소개·포부·윤리강령 입력저장)
- 메인화면 카드 **"🙋 소개하기"** → 전용 화면.
- 섹션(고정 목록): 자기소개 / 마지막 포부 / 기술사 윤리강령 6항 / 수치근거·두문자 암기(자유).
- 각 섹션 `<textarea>` + 저장. `localStorage["iv:intro"]`(JSON). 초기값은 docx 자료로 **시드**(사용자가 편집 가능).
- 보기/편집 토글. 기존 학습화면과 독립(격리) — 별도 `iv-intro-screen` 섹션.

메인 카드 순서(권장): 이력연계 · 예상토픽 · 전체 · ⭐선택토픽 · 🙋소개하기.

## C. 실행 전략 (멀티에이전트 워크플로우)

사용자 동의(opt-in) 확인됨. 선행 계획의 4단 파이프라인을 재사용·확장한다.

1. **샘플 락(먼저)** — 이력 1 + 예상 1을 신규 스타일로 완성 → **사용자 승인**으로 스타일·길이 확정.
2. **UI 3기능 구현**(B-1/2/3) → `npm run check` + 수동 확인(스크린샷).
3. **대량 생성(워크플로우)** — 이력 8블록 + 예상 8도메인 병렬 생성 → 적대적 검증(기출정합·이력적합·시의성) → 길이·두괄식 린트 → JSON 주입.
4. **검증** — `npm run check` 통과, `npm run test:e2e` 핵심 흐름 + 스크린샷.

- `npm run check`: JS 구문 + 면접 데이터 무결성(배열·유일 id·question·references) 0 오류.
- `npm run test:e2e`: 모드선택→학습→정답보기 흐름 + 선택토픽·소개하기 스모크 + 스크린샷.
