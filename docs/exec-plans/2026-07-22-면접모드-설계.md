# exec-plan: 면접 모드 v1 — 설계

- 날짜: 2026-07-22
- 유형: 신규 기능 설계 (구현 계획은 후속 writing-plans 로 분리)
- 제약: **기존 앱 동작 변경 0** — `flash.html`·`js/flash.js`·`data/cards/*`·`admin.js` 무수정 (절대규칙 1)
- 참조: 경쟁/레퍼런스 분석 대상 [`itpe-interview.web.app`](https://itpe-interview.web.app/) — 정보관리기술사 "구술(면접)" 대비 Flash 앱

## 배경

우리 앱 `ITPE Flash` 는 **필기·개념 암기**(정의/두문자/키워드) 중심이다. 레퍼런스 사이트
`itpe-interview.web.app` (Vue3+Vite, 백엔드 없음, 145문항 번들 내장)를 정적분석·렌더링으로
면밀히 분석한 결과, 핵심 가치는 **"구조화된 구술 답변 템플릿"** — 단순 정의가 아니라
면접장에서 말하는 순서(복명복창 → 목차 → 개념 → 실무사례)를 색상 라벨로 코칭하는 것이었다.
이 가치를 **새 앱 없이 우리 기존 무빌드·0원·정적 자산 위에 "면접 모드"로 얹는다.**

## 목표 / 비목표

**목표(v1)**
- 면접 문항을 카테고리별(이력기반=순서, 예상토픽=셔플)·전체(셔플)로 출제
- 카드에서 `정답 보기` → **4단 색상 구술 템플릿**(복명복창/구조화/개념/실사례) 노출
- 기존 앱과 동일한 로그인 게이트·회전 제어·다크 룩앤필
- 백엔드 0 / API 0 — 정적 JSON 만 읽어 오프라인 동작

**비목표(v2 이후)**
- 🎤 모의면접 20분 타이머 세션(자기소개→질문10→포부)
- 관리도구(admin) 면접 카드 CRUD
- 체크/별표/오답노트/진도 계정 동기화(R2)
- TTS 음성 읽기

## 아키텍처 (기존 무빌드·바닐라 패턴 미러)

- **`interview.html`** — `flash.html` 축약판. `css/style.css` 재사용 + 소량 전용 스타일(`css/interview.css`).
  헤드에 `js/auth.js`(로그인 게이트) + `js/orientation.js`(회전) 로드 → **기존 앱과 동일 접근권한·UX 톤**.
- **`js/interview.js`** — **클래식 스크립트 IIFE**(ESM import/export 금지 — AGENTS 함정 준수).
  자기완결형: 매니페스트+문항 JSON 로드 → `order` 빌드 → 렌더/공개/이전·다음/다시섞기.
  `flash.js` 는 **참조도 하지 않음**(코드 격리, Rule 1 안전).
- **정적 서빙** — `interview.html` 은 단순 정적 파일. 기존 Vercel 정적 서빙·`sw.js`·PWA 그대로 활용.
  운영 API 불필요(레퍼런스와 동일한 "데이터 전량 클라이언트" 접근).

## 데이터 모델

```jsonc
// data/interview/index.json  — 매니페스트 (data/index.json 패턴 미러)
{
  "title": "기술사 면접 대비",
  "categories": [
    { "id": "career",   "name": "이력기반", "emoji": "📋", "file": "career.json",   "mode": "sequence", "description": "이력/경력 기반 예상 질문" },
    { "id": "expected", "name": "예상토픽", "emoji": "🎲", "file": "expected.json", "mode": "shuffle",  "description": "예상 토픽 문항" }
  ]
}

// data/interview/career.json | expected.json  — 문항 배열
[
  {
    "id": "iv-0001",
    "category": "예상토픽",         // "이력기반" | "예상토픽"
    "question": "클라우드 전환 6R 전략을 설명하고 실제 수행 전략을 말씀해 주세요.",
    "restate":   "…에 대하여 설명 드리겠습니다.",      // 복명복창 — 답변 시작 멘트
    "structure": "…, … 순서로 말씀 드리겠습니다.",       // 구조화   — 답변 목차
    "concept":   "…",                                   // 개념     — 핵심 개념 설명
    "case":      "…",                                   // 실사례   — 실무 경험/사례
    "references": []                                    // 선택 — 빈 값은 렌더 시 자동 숨김
  }
]
```

- 필수 필드: `id`, `question`. 나머지 4단 필드는 **있는 것만** 렌더(빈 필드 자동 숨김).
- `id` 는 파일 내 유일. 초기엔 각 파일에 오탈자 없는 **샘플 5개**만 채워 틀을 제시.
- "전체" 모드는 별도 파일 없이 두 카테고리를 런타임 병합.

## 화면 (3)

1. **홈 진입** — `index.html` 에 **`🎤 면접 대비`** 버튼 1개 가산 → `interview.html`.
   (flash 학습 흐름과 무관한 위치, 기존 동작 불변.)
2. **모드 선택** (`interview.html` 첫 화면) — 카드 3장:
   `📋 이력기반(순서)` · `🎲 예상토픽(셔플)` · `🔀 전체(셔플)`. (모의면접 카드 = v1 미노출.)
3. **학습 화면** — 헤더(`← 홈` / 카테고리명 / `↻ 다시섞기`) · 진행바 `n / N` ·
   질문 카드(카테고리 뱃지 + 질문) · **`정답 보기`**(공개 전 힌트 "먼저 스스로 답변을 구성해 보세요") ·
   공개 시 **4단 색상 템플릿** · 하단 `이전`/`다음`.

## 4단 구술 템플릿 (레퍼런스 방식 채택)

| key | 라벨 | 힌트 | 색 토큰 |
|---|---|---|---|
| `restate`   | 복명복창 | 답변 시작 멘트   | 파랑 (`--accent`) |
| `structure` | 구조화   | 답변 목차       | 초록 |
| `concept`   | 개념     | 핵심 개념 설명   | 보라 |
| `case`      | 실사례   | 실무 경험/사례   | 금색 |

각 단은 색상 라벨(칩) + 회색 힌트 + 본문(좌측 색 바)으로 렌더. `css/style.css` 의 기존 토큰 재사용.

## 상태·지속 (최소)

- URL 파라미터 `?cat=<career|expected|all>&mode=<sequence|shuffle>` → 새로고침 시 위치·모드 유지(`flash.html` 방식 미러).
  ("전체" 모드 = `cat=all` + `mode=shuffle`, 두 카테고리를 런타임 병합.)
- 셔플은 세션 내 고정(다시섞기 버튼으로만 재셔플) — 레퍼런스와 동일 UX.
- 체크/별표/진도/TTS 미포함(YAGNI).

## 검증

- **훅(자동)**: `js/interview.js` 저장 시 `node --check`, `data/interview/*.json` JSON 파싱.
- **`npm run check`**: `scripts/check.mjs` 에 면접 JSON 무결성 추가 —
  필수 필드(`id`/`question`) 존재, `id` 유일성, `category` 유효값, 매니페스트↔파일 정합성.
- **E2E** (`tests/e2e/interview.spec.mjs`, 기존 정적 서버 하네스 재사용):
  로그인 시드 → `🎤 면접 대비` 진입 → 이력기반 → `정답 보기` → 4단 노출 확인 → `다음` →
  URL `?cat&mode` 유지. 각 단계 스크린샷 `test-results/screens/` 저장.

## 작업 단계 (개요 — 상세는 후속 구현 계획서)

1. 데이터 스캐폴드: `data/interview/{index,career,expected}.json` + 샘플 5×2

3. `interview.html` + `css/interview.css` + `js/interview.js` (모드선택 → 학습 → 4단 템플릿)
4. `index.html` 진입 버튼 가산
5. `tests/e2e/interview.spec.mjs` + 스크린샷 증빙
6. `npm run check` + E2E 통과 확인 → 관련 파일만 커밋
