- 날짜: 2026-07-26
- 유형: 앱 기능 추가/개선
- 트리거: 139회 실기(면접) 임박. 자기소개·포부는 **완전 암기** 대상 → 카드로 넘기며 반복 + 귀로 회독.
- 선행: `2026-07-26-면접문항-300-재구성-회독최적화.md`(소개하기 v1: 긴 스크롤 편집 화면), `2026-07-26-면접자료-인쇄.md`

## 목표

1. **소개하기를 플래시카드 형태로** — 한 번에 한 섹션, 넘기며 낭독 연습. **수정은 계속 가능**.
2. **TTS 탑재** — 소개하기 카드 · 면접 문항 질문 · 4단 답변 전문을 음성으로 듣기.

## 절대규칙 준수

- **동작 임의 변경 금지(규칙1)** — 학습 화면 헤더(← 홈·☆·🖨·↻)와 하단 툴바(이전/정답 보기/다음)는 **불변**.
  TTS 조작은 질문 아래 새 줄에만 배치. 소개하기는 사용자가 명시 요청한 화면 교체.
- **무빌드·0원(규칙6)** — 브라우저 내장 Web Speech API 사용. 신규 패키지·외부 출처 **없음** → CSP 변경 불필요.
- `js/tts.js` 는 클래식 스크립트 IIFE(ESM 금지), `window.ITPETts` 전역.

## 설계

### 1) 공용 TTS 모듈 `js/tts.js` (신규)

`window.ITPETts = { supported, speak, stop, isSpeaking, getRate, setRate, onChange }`

- **음성 선택** — `getVoices()` 중 `lang^=ko` · `localService`(오프라인) 우선. `getVoices()` 는 비동기라
  첫 호출이 비면 `voiceschanged` 로 재선택.
- **긴 텍스트 분할** — 크롬은 긴 utterance 를 15초쯤 끊는 알려진 버그가 있다.
  문장(→ 너무 길면 쉼표/공백) 단위 **80자 내외**로 쪼개 `onend` 로 이어 읽고,
  안전장치로 재생 중 주기적 `resume()` 호출. 조각 하나가 실패해도 다음으로 진행(`onerror`).
- **속도** — 0.8/1.0/1.2/1.5x, `localStorage["iv:ttsRate"]`. 재생 중 변경하면 남은 분량부터 새 속도로.
- `pagehide`/`beforeunload` 에서 정지 — 화면을 떠난 뒤에도 계속 읽히는 것 방지.

### 2) 소개하기 — 카드 + ✏️ 편집 토글

- 화면: 헤더(← 홈 · 소개하기 · **✏️**) + 진행바 `n / 4` + 카드 + 하단바(**이전 / ▶ 듣기 / 다음**).
- 카드: 라벨 배지 + 힌트 + 본문(큰 글씨 1.12rem·행간 1.75) + 낭독 속도 선택.
- **✏️** 를 누르면 같은 자리가 `textarea` 로 바뀌고 입력 즉시 `localStorage["iv:intro"]` 자동 저장.
  편집 상태는 카드를 넘겨도 **유지**(연속 수정 편의). 새로고침하면 읽기 모드로 복귀.
- 하단바는 학습 화면 툴바와 **별도 엘리먼트**(`#iv-intro-toolbar`) — 기존 툴바 동작에 영향 없음.

### 3) 면접 문항 — 질문·답변 낭독

- 질문 아래 한 줄: `[🔊 질문] [🔊 답변] [속도]`. 답변 버튼은 **정답 공개 후** 활성.
- 답변 낭독은 4단(복명복창→구조화→개념→실사례)을 순서대로 이어 읽는다. 키워드·압박대응은 제외.
- 같은 버튼을 다시 누르면 **정지**(라벨이 `■ 정지` 로 바뀜). 카드를 넘기면 자동 정지.

**검증**
- `npm run check`: JS 구문 **30/30 통과**. 데이터 오류 2건(`data/cards/12.json`·`13.json` 없음)은
  관리도구발 **기존 문제**로 이번 작업과 무관.
- `npm run test:e2e`: **13/13 통과**. TTS 는 헤드리스에 한국어 음성이 없으므로 `speechSynthesis.speak` 를
  스텁해 **전달된 텍스트를 검증** — 조각을 합치면 질문/본문 원문과 **글자 단위로 일치**함을 확인(무손실 분할).
- 실제 브라우저(설치된 Chrome) 확인: 한국어 음성 `Microsoft Heami - Korean (ko-KR)` 사용 가능.
- 스크린샷: `test-results/screens/` 의 `tts-intro-card.png`, `tts-intro-edit.png`, `tts-question-bar.png`, `iv-9-tts.png`.

**알려진 제약**
- 브라우저·OS 에 한국어 TTS 음성이 없으면 낭독 바가 떠도 소리가 나지 않는다(엔진 부재).
  `ITPETts.supported()` 는 API 존재만 판단하므로 음성 유무까지는 막지 않는다.
- iOS Safari 는 첫 재생이 사용자 제스처 안에서 일어나야 한다 — 버튼 클릭으로 시작하므로 충족.
