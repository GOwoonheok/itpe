# exec-plan: 139회 면접 문항집 생성 + 엑셀 내보내기

- 날짜: 2026-07-23
- 유형: 콘텐츠 생성(면접 문항 데이터) + 스크립트 신설(엑셀 내보내기)
- 제약: **기존 앱 동작 변경 0** — `js/interview.js`·`interview.html`·`css/*` 무수정 (절대규칙 1).
  `data/interview/*.json` 은 v1 설계상 "사용자 직접 작성" 슬롯이므로 **콘텐츠 채우기**에 해당.
- 트리거: 139회 실기(면접) D-7. 수검자 이력카드 + 134~138회 기출 852문항 보유.

## 배경

`docs/exec-plans/2026-07-22-면접모드-설계.md` 로 면접 모드 v1(출제 3모드 + 4단 구술 답변뷰)을
구현했으나, 콘텐츠는 카테고리별 **샘플 5문항**뿐이었다(설계 결정 #4 "초기 콘텐츠는 사용자 직접 작성").
이번 작업은 그 빈 슬롯을 **실데이터로 채우고**, 앱 밖에서도 볼 수 있도록 **엑셀로 내보낸다**.

입력 자료:
| 파일 | 내용 |
|---|---|
| `data/면접자료/면접질문_총괄.xlsx` | 134~138회 기출 852문항 (회차/구분/질의내용/답변내용). 답변 컬럼에 **합격자 자기평가와 면접관 반응**이 함께 기록되어 있어 채점 신호로 활용 가능 |
| `data/면접자료/(공공)139회 고운혁 이력카드(V1.22).pdf` | 수검자 이력카드 — 경력 5블록 + 세부실무경력(수상/전문관/박사논문/차세대나라장터/e-발주) |

## 접근

기출을 "읽고 감으로 예상"하지 않고, **852문항 전수 분석 → 예측 → 적대적 검증 → 답변 작성**의
4단 파이프라인을 다중 에이전트 워크플로로 실행한다.

| 단계 | 방법 | 산출 |
|---|---|---|
| 1. 기출해부 | 회차별 5 + 토픽 5분할 + 이력 3분할 + 포부 + 감점패턴 역공학 = 15 에이전트 병렬 | 도메인 분포·질문유형 분포·이력 공격 프레임·면접관 압박 기법·감점 사유 |
| 2. 예측 | 이력 8블록 + 토픽 8도메인 = 16 에이전트. 1단계 결과와 이력카드를 근거로 예상문제 생성 | 후보 문항 풀(질문/근거/함정/꼬리질문/필수키워드) |
| 3. 검증 | 후보를 26개씩 배치로 나눠 **3렌즈 판정단**(기출정합·이력적합·시의성) 적대적 채점 | 문항별 출제확률(0~100) 3인 평균 |
| 4. 답변작성 | 상위 문항(블록당 최대 8, 총 ~110)에 4단 구술답변 작성 | `restate/structure/concept/case` + 꼬리질문 대비 + 함정 |
| 5. 종합 | 문서 4종 + 앱 주입용 JSON 2종 | 아래 산출물 |

판정단은 "평균 확률이 45를 넘으면 검증 실패"로 프롬프트해 과대평가를 억제했다.
